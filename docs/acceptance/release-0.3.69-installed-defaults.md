# Latest 0.3.69: installed defaults reach their release pins

Latest only. Stable stays 0.3.65. This snapshot deliberately takes the **0.3.67** runtime pins and changes only the host-installed App Manager source to `08b54f65d70b` (full SHA in the manifest), on `maintenance/claude-upgrade-release-pins`. The version was reserved on #251 after a concurrent 0.3.68 cut. The newer UX, Agent Service and connection-app pins from 0.3.68 are not included; do not call this a superset of 0.3.68.

## Cause and repair

The preserved disposable 0.3.39 -> 0.3.67 run selected Claude for update, so neither optional-app status nor being signed out caused the failure. Its saved old form lacked the new required Hermes dashboard password. The backend rolled back to Claude 0.1.2. The CLI counted the restored running status as success, while registry projection preferred the prepared store's new manifest. Importing a clean box's backup correctly refused to restore Claude 0.2.6 into that older installed app.

WAM #267 reconciles required inputs using the existing form/shared-input rules and update-config API, preserves saved settings and stopped state, and checks the actual installed commit and manifest version after the queued update. Registry projection prefers installed metadata. Existing generated secrets are retained and reused. The exact release source is the reviewed patch applied to `da2f01d1`; unrelated main changes and the later Hermes update policy are excluded. The main-only Hermes policy tests were not added to this older source branch. No backend image inputs changed, as verified by the online release checker against the existing official attested image.

A clean 0.3.65 already includes Claude 0.2.6. A box upgraded to 0.3.65 from an older version can retain the same latent 0.1.2 drift, so the fix also reconciles that case. The staged tests include 0.3.65 -> this candidate rather than assuming stable installations are clean.

OS #268 checks actual installed default app manifest versions and source commits before every journey, including the upgraded case. It ignores the prepared store projection, and remembers baseline installed defaults so disappearance fails too. Both the baseline releases (0.3.39, 0.3.40, 0.3.65) and 0.3.67 source manifests were fetched at their exact pins and agree with `index_version` (30 baseline entries and 12 candidate entries).
