# Builder app appearance — candidate consumer

James asked the App builder lane on 12 October 2026 to default new apps to the skin of the containing Wizard OS, as an MVP. The WAM template consumes App styling's proposed appearance v1 client and semantic CSS roles; it does not introduce another theme system or approve the full skin/platform proposal.

Same-origin parent ready/appearance/ack handshake, payload and monotonic-revision validation, appearance-only values, dark Nebula standalone fallback. Host resolves skin; app keeps layout, data and reading/display fonts. Window surfaces expose the container; fullscreen uses opaque skin canvas. No shell selectors/globals in app source; generic controls use UI role, text/surface/border/accent/on-accent/radius.

Proof: actual builder-generated habit container, copied real App styling shell/skins host, all six palettes at phone and desktop viewport, state/draft/scroll without reload, wrong-source/origin/stale payload refusal, fullscreen/Back and visible app reopen. Two disposable Ubuntu source-bundle installs verify actual API/MCP and restart persistence. This is developer staging, not production lifecycle/public catalog rollout. See WAM#16 for exact candidate and receipts.

Integration seam: preserve system-skills in stock skills.external_dirs, and ship/register the shared host adapter through its own owner. Daily remains unchanged. Expanded font roles, shared control library, multi-origin trust configuration and full view override/update serving are future increments.
