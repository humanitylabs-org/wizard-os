# Wizard box credentials and recovery

This is a **location and recovery map, never a place to record secret values**. Read [the repair runbook](docs/REPAIR.md) before changing a login. Paths below are defaults, not proof of a particular box's layout. Discover the actual owner account, `WIZARD_OS_HOME`, `RUNTIPI_ROOT`, alongside metadata and container mounts first. Do not run repair as a different account and accidentally create a second installation.

## Owner-held versus generated

The owner retains their OS administrator login, SSH private key, Tailscale account/recovery methods, Claude/ChatGPT account and MFA, backup decryption key, and any publishing/signing identity. Wizard cannot recreate these. Generated box tokens and operator passwords can be replaced, but every consumer must be updated together. **A backup on the same failed disk is not recovery.** Keep the encrypted backup and its recovery key separately, off the box, and rehearse a stopped restore before relying on it.

| Credential or state | Actual source / default location | Ownership and recovery |
|---|---|---|
| SSH and OS access | SSH client's private key on the owner's device; target account's `~/.ssh/authorized_keys`; host SSH configuration. These are host administration, not WAM-created credentials. | Owner/admin-held. Add a replacement public key through an already working session or local VM console, test a second session, then remove the old key. Never remove the last working access method. Mac host login and Linux guest login are different. |
| Hermes provider OAuth pools | **Actual** `$HERMES_HOME/auth.json`; API keys may also be in `$HERMES_HOME/.env` or provider settings in `config.yaml`. Alongside: the existing owner's Hermes home from `~/.wizard-os/alongside.json`. Fresh main app: `<RUNTIPI_ROOT>/app-data/wizardapps/hermes-agent/data` in the current WAM store (confirm store name/mounts). Managed additional agents follow their `agent.json`, not this main-app default. | Owner signs into provider; Hermes writes/refreshes tokens. Use the installed `hermes auth --help`, `hermes auth list openai-codex`, and `hermes auth add openai-codex` in that same runtime/home. List output may contain account labels: keep it private. Do not delete auth.json or copy rotating refresh tokens between homes. Revoke a compromised session at the provider, re-login, and verify a real request. |
| Hermes local API | `API_SERVER_KEY` in the actual Hermes home's `.env`; the corresponding Agent Service value is `WIZARD_HERMES_API_KEY`. WAM alongside discovers it through `alongside.api_key`; `wizard link` adds one if absent. | Generated or owner-provisioned. Replace the API server key and its Service consumer together, restart only after checking active work, and verify an authenticated request. Never set an empty key or disable authentication to bypass a mismatch. |
| Claude connection app | Fresh: Docker volume **`wizard-ai-accounts-claude`**, mounted `/claude` in the connection engine (shared with main Hermes). Alongside: WAM PR #110 uses the host Hermes' `CLAUDE_SUBSCRIPTION_DIRECTSDK_CONFIG_DIR`, then `CLAUDE_CONFIG_DIR`, then `~/.claude`, via a user-config override. | Owner-held Claude account, generated rotating login. Open Claude → Test (renew), then Connect if needed. The app and host must use the **same folder**, not copied credentials. Check the mount after a re-login. Host Claude Code repair login can be separate on a fresh box; connection-app success does not prove the repair CLI is signed in. |
| ChatGPT connection app | The app holds **no ChatGPT OAuth token**. It drives the actual Hermes dashboard/device login; tokens remain in that Hermes auth store. Fresh URL defaults to `http://hermes-agent:9119`; alongside uses the host dashboard. | Owner opens ChatGPT → Connect and completes provider sign-in on their own device. Test the agent too. A standalone `codex login` creates a separate CLI login; it does not repair Hermes auth automatically. Never request a verification code in chat. |
| Standalone emergency CLI login | Claude Code's native config directory (`CLAUDE_CONFIG_DIR`, otherwise `~/.claude`); Codex's native home (`CODEX_HOME`, otherwise `~/.codex`). Platform keychains may hold Claude credentials: there is no universal portable Claude token filename. | Owner performs `claude auth login` or `codex login` on the repair runtime; inspect installed help first. Use `claude auth status` / `codex login status`. Revoke via the provider and re-login to rotate. Do not copy the agent's provider tokens into either CLI. Wizard does not install or license these CLIs by virtue of installing a connection app. |
| WAM HTTP mutation token | `<WIZARD_OS_HOME>/api-token` (default `~/.wizard-os/api-token`), generated 0600 by `Config.api_token`. WAM API default is loopback `:7790`. | Generated. For compromise, stop `wizard-app-manager-api.service`, replace the file securely with a fresh random value (0600), update authorized clients, start the service and test authorized **and unauthorized** calls. Restart is necessary because the server snapshots the token. Never expose this API through a tunnel. |
| WAM → Runtipi operator | `~/.wizard-os/runtipi-operator.json` (0600), initially random password for `owner@wizard.local` when WAM registers an operator. Existing boxes may already have an operator, so absence does not imply lost data. | Generated password; owner may change it. Recover through Runtipi's supported dashboard/reset-password CLI after reading `wam --help` / `wam reset-password --help`; not by editing the database. Keep owner login and saved credential record consistent. |
| Runtipi JWT signing secret / database credentials | `<RUNTIPI_ROOT>/.env` (`JWT_SECRET` is read by WAM's Runtipi client). Other Runtipi environment/database credentials are managed by Runtipi, not the app registry. | Generated by base install. Do **not** delete/regenerate .env to fix a 401. Use Runtipi's supported recovery procedure for the installed version; JWT rotation invalidates sessions and may have other consumers. Database password rotation needs a coordinated database + environment change and a verified backup. |
| App passwords and install form secrets | `<WIZARD_OS_HOME>/secrets/<app-id>.json`; Runtipi per-app `app.env` / generated compose; owner overrides in `<RUNTIPI_ROOT>/user-config/<store>/<app>/app.env`. | WAM generates missing required password fields, but individual apps also have `random` fields managed by Runtipi. Rotate using the app's supported settings and WAM/Runtipi configuration, then restart/update only that app. Rewriting a JSON record alone does not rotate the running app. Treat all app-data and user-config as secret-bearing. |
| Host Hermes dashboard basic auth | `<WIZARD_OS_HOME>/secrets/host-dashboard.env` (0600): username/password plus session signing secret. Consumers receive matching values in their Runtipi user-config. Unit `wizard-host-dashboard.service`. | Generated by `wam/host_dashboard.py`. Stop the dashboard, securely replace the necessary values, re-run `wam alongside` to propagate, apply the exact app-update instructions it prints, restart and test. Do not delete the file casually: this can desynchronize app clients. |
| Wizard MCP gateway token | `<WIZARD_OS_HOME>/mcp-token`, host Hermes MCP config and Agent Service `WIZARD_MCP_TOKEN` / its user-config app.env. | Generated. Re-link through `wizard link` / `wam alongside` after a coordinated replacement; confirm installed help and actual mode first. Existing consumers must all move together. Never publish it in a repair prompt. `wizard unlink` is an intentional undo, not a doctor command. |
| Agent Service internal credentials | `WIZARD_HERMES_API_KEY`, optional `WIZARD_INBOX_INTERNAL_TOKEN`, `WIZARD_AGENT_RUNTIME_TOKEN[_FILE]`, `WIZARD_AGENT_DELIVERY_TOKEN[_FILE]`, `WIZARD_OWNER_PROOF_FILE`, `WIZARD_HEAVY_TOKEN`; values are deployment-specific environment / secret files. Per-app delivery files: `<wizard-os home>/app-tokens/<app-id>`. | Generated or provisioned by that deployment. Discover **names and paths only**, not `docker inspect .Config.Env` or `systemctl show Environment`. Rotate producer + consumer atomically in an approved maintenance window; there is no universal WAM rotate-all command. Never weaken auth to make a health check green. |
| Tailscale | Standard Linux host: root-managed `tailscaled` state (normally `/var/lib/tailscale/tailscaled.state`) and `/var/run/tailscale/tailscaled.sock`. Custom gateways can use a user unit/socket instead. Confirm service configuration; do not print or copy its state. | Owner account held off-box; node key generated. Reconnect with the installed Tailscale client and owner approval (`sudo tailscale up` for WAM's standard host setup). Revoke a compromised node in the owner's tailnet admin console. Do not run logout on your only remote route; use a local console or independent SSH path first. Keep Serve configuration. |
| Troubleshooter | Host install: `~/.local/state/wizard-troubleshooter/guardian.token`, conversations and incidents; service drop-ins carry host configuration. | Generated token plus private diagnostic history. Not a provider login. Protect state 0700/files 0600. Rotate guardian token only with the guardian stopped; it reads the same file. Preserve repair history. A normal isolated app container has no authority to restart host services; see the packaging gate in the runbook. |
| GitHub / container registry | `gh`'s OS credential store or native config (commonly `~/.config/gh/hosts.yml` on Linux); optional `GH_TOKEN` / `GITHUB_TOKEN`. WAM private image pulls use temporary Docker config. Owner's Docker config may also contain registry credentials. | Owner/team-held access. Use `gh auth status`, `gh auth login`, or `gh auth refresh -s read:packages` for private images, without printing `gh auth token`. Revoke old PAT/OAuth grants at GitHub. Public installation must not depend on a team member's private-repo access. |
| Publishing/signing / Wizard ID | Wizard ID private key is phone-side, Android Keystore wrapped with owner password-manager recovery; see [WIZARD_ID](spec/WIZARD_ID.md). Repository CI release signing keys are publisher/CI secrets, **not** credentials that every box should receive. | Owner/publisher-held. Wizard cannot reset a lost Nostr identity. Never create a replacement and call it the same identity. Verify signatures against an independently trusted release key; do not bypass a failed signature. Mac developer signing/notarization credentials belong to the publisher's build system, not the Linux guest. |
| Backup encryption keys | Backup-tool-specific, owner-selected destination and secret manager. There is no universal key file or completed whole-box restore command in WAM. | Owner-held, separate from encrypted backups and the box. Re-encrypt/rotate per that backup tool; preserve the old key until retained backups expire. Without the original key, encrypted data cannot be recovered by re-login. |

## What to preserve even when the app is broken

Preserve the actual Hermes home (including SQLite DB, WAL/SHM, auth, config, profiles, memory, skills, sessions and cron), `<WIZARD_OS_HOME>/agents`, registry/config/alongside/linked metadata, Runtipi `.env`, `app-data`, `user-config`, named volumes, media, backups and release provenance. Agent Service state includes a durable run queue and uploads; deleting them can lose accepted work or duplicate it on retry. Back up databases through their native online-backup mechanism or while their writer is stopped, not by copying a live SQLite main file alone.
